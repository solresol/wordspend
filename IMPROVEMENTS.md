# IMPROVEMENTS.md

*Analysis date: 2026-07-11*

`wordspend` is a quantitative-humanities project measuring relative lexical
compression across translations: it fits `log(T+1) = alpha + beta·log(S+1)` on
aligned source/translation segments and studies residuals. Current state: a
young but well-organized repo (6 commits) with a Python package
(`wordspend/`), PostgreSQL schema, pipeline scripts, a static-site generator
targeting `wordspend.symmachus.org` on merah, provenance for two Iliad
translations (Butler, Pope), and a paper draft. Working tree is clean. The
project already uses `uv` with `pyproject.toml` — good. The critical gap is
that the test suite does not run at all in the project environment, and the
scientific core (tokenization/alignment) is still unbuilt.

## Bugs & Fixes

1. **Tests cannot run: `uv run pytest` fails to import `wordspend`.**
   Both `tests/test_analysis.py` and `tests/test_prepared_texts.py` fail
   collection with `ModuleNotFoundError: No module named 'wordspend'` because
   pytest is not a project dependency — `uv run pytest` falls through to the
   Anaconda system pytest (`~/anaconda3/lib/python3.11`), which runs outside
   the uv venv. Fix: `uv add --dev pytest` and commit the resulting
   `pyproject.toml`/`uv.lock`. This also means CI (if any) is not validating
   anything.
2. **`scripts/run_daily_pipeline.sh` silently swallows pull failures**
   (`git pull --ff-only -q || true`). A wedged checkout will keep publishing
   stale analysis to merah with no signal. At minimum log the failure to
   `logs/` and/or set a nonzero exit or notification.
3. **`wordspend/db.py::apply_schema` executes whole schema files without
   migration tracking.** With two files in `schema/`, nothing records which
   have been applied; re-running `init_db.py` presumably relies on every
   statement being idempotent. Add a `schema_migrations` table (matching the
   convention used in your stephanos project) so `003_*.sql` onward can be
   non-idempotent.

## Improvements

- **Build the tokenize/align step** — the top open TODO.md item and the
  project's actual scientific bottleneck. Nothing in `wordspend/` yet aligns
  Greek source segments to the prepared Butler/Pope bodies; `analysis.py`
  assumes aligned rows already exist. Decide on the alignment unit (Perseus
  book/line ranges vs. paragraph) and record alignment provenance in the DB
  like you did for text provenance.
- **`wordspend/textstats.py` length metrics are Latin-script naive** for the
  Greek side (word tokenization by whitespace inflates/deflates counts for
  crasis, elision, enclitics). Document the tokenization rule per language in
  `docs/methods.md` and encode it in `data/text_preparation_rules.csv`.
- **`machine_bootstrap` exclusion** (second open TODO item): enforce it in
  `scripts/select_paper_facing_translation_texts.py` with a test, not just
  policy prose in `docs/translation-policy.md`, so a future machine-generated
  row can never leak into paper-facing output.
- **`import_pausanias.py` couples this repo to the pausanias DB** via
  `PAUSANIAS_DATABASE_URL`; note in `docs/operations.md` that both DBs live on
  raksasa and what happens when pausanias is absent (`IMPORT_PAUSANIAS=0`
  default is good — document it).

## Security

- No committed secrets found: DB access uses `WORDSPEND_DATABASE_URL` with a
  local peer-auth default (`dbname=wordspend`) — good.
- The rsync/deploy target `wordspend@merah:...` is embedded in
  `run_daily_pipeline.sh`; fine, but ensure the merah-side account is
  write-restricted to the vhost htdocs (no CGI planned, keep it that way).
- Downloaded Gutenberg texts are verified by checksum in
  `fetch_translation_sources.py` provenance — good practice; keep requiring
  checksum match before promotion to `data/prepared/`.
